     Product Entry Rules — Quick Guide
    

    

     Use this as the short operating standard for product lookup, entry, order history, and editing.
    

    

     

      1. Core Rule
     

     
    
      
  • 
       
        Product Catalog
       
       = one row per unique physical item.
      
    • 
      
  • 
       
        Order History
       
       = one row per purchase/order event.
      
    • 
      
  • 
       A repeat purchase uses the same product ID and gets a new history row.
      
    • 
     

    

    

     

      2. Product Fields
     

     
    
      
  • 
       Enter the product identity only: family, department, category, subcategory, size, thickness, length, material, and color.
      
    • 
      
  • 
       Leave unknown values blank. Do not guess.
      
    • 
      
  • 
       Color field is for color/finish only.
      
    • 
     

    

    

     

      3. Order History Fields
     

     
    
      
  • 
       Enter purchase details: vendor, SKU, cost, unit, order date, quantity, job tags, notes, and purchase link.
      
    • 
      
  • 
       Vendor, SKU, cost, date, and job do not define the product.
      
    • 
      
  • 
       Cost/vendor/SKU changes require a new history row, not a new product.
      
    • 
     

    

    

     

      4. Naming
     

     
    
      
  • 
       Canonical names are generated from structured product fields.
      
    • 
      
  • 
       Do not include vendor, SKU, cost, job, order date, shipping, tax, or fees in the product name.
      
    • 
      
  • 
       Use clear product families such as Acrylic Sheet, Button Head Screw, or T-Slot Aluminum Profile.
      
    • 
     

    

    

     

      5. Duplicate Decision
     

     
    
      
  • 
       If the physical product matches, reuse the existing internal_id.
      
    • 
      
  • 
       If only purchase details changed, add Order History only.
      
    • 
      
  • 
       If size, material, color, or other physical attributes differ, create a new product item.
      
    • 
      
  • 
       If uncertain, flag for manual review before assigning an ID.
      
    • 
     

    

    

     

      6. Job Tags
     

     
    
      
  • 
       Use job number only, e.g., J1526.
      
    • 
      
  • 
       Use comma-separated unique tags when multiple jobs apply.
      
    • 
      
  • 
       When an existing product is used on a new job, update product job tags and add a history row.
      
    • 
     

    

    

     

      7. Do Not Enter
     

     
    
      
  • 
       Do not create product entries for shipping, tax, tariffs, fees, or non-product charges.
      
    • 
      
  • 
       Custom items may be entered only if they may be reused or referenced later.
      
    • 
     

    

    

     

      8. Website Workflow
     

     
    
      
  • 
       
        Lookup:
       
       search or filter by product, vendor, SKU, job, category, or subcategory.
      
    • 
      
  • 
       
        Add Order History:
       
       use this for repeat purchases of an existing product.
      
    • 
      
  • 
       
        Edit Product:
       
       use only to correct product identity/attributes.
      
    • 
      
  • 
       
        Edit History:
       
       use only to correct one purchase event.
      
    • 
     

    

    

     

      9. Save Rule
     

     
    
      
  • 
       Connect the data folder when possible so saves write back to the JSON files.
      
    • 
      
  • 
       If not connected, saves may remain in browser cache until exported/downloaded.
      
    • 
     

    

    

     

      Quick Decision Flow
     

     
Receipt / Order Line
↓
Shipping, tax, tariff, or fee?
YES → Omit from product lookup
NO
↓
Classify Department → Category → Subcategory
↓
Enter known product attributes only
↓
Does the same physical product already exist?
YES → Reuse internal_id + add Order History
NO
↓
Create new product + add first Order History

If unsure at any point → Manual Review

    

    

     

      One-Line Rule
     

     

      
       Same physical item = same product ID; every purchase = a new order history row.
